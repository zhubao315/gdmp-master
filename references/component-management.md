> **证据状态**：文档推导（组件中心 / 组件体系功能描述） · 已验证（WAR 无 Skill 组件；故障处置 SQL 来自文档） · 待确认（运行时组件台账 / 后台凭据） · 不适用。
> **知识包性质**：版本化运维知识包，非 AI 可执行 Skill；GDMP 无 AI Agent / Skill 加载器，不得宣称 AI 执行。
> **变更基线**：生产默认只读；变更须审批；先 dry-run；数据库与应用回滚分别制定、不得默认互逆。

## 1 组件体系（文档推导 → 待确认）
- 模块范畴：组件库、自定义组件、安装、依赖、版本、兼容（文档站模块清单）。
- 组件中心：文档称 500+ 功能组件（页面 / 业务 / 图表 / 地图 / 打印等），支持自定义扩展；两大中心（总中心统筹、分中心自治）见内容生态文档。
- 组件来源：应用中心 / 组件中心 / 模板中心 / 知识中心；五大资源库含「功能插件库」（即时通讯、OCR、爬虫、地图、支付等扩展）。
- 上述数量为产品文档口径，未运行时枚举 → **待确认**。

## 2 组件与「AI Skill」的区别（决定性）
- 自定义组件 / 功能插件是平台扩展机制（文档称扩展中心可接入 AI、IoT 等外部系统），**不等于本机 AI Skill Runtime**（R1）。
- WAR `AI_ROOT_20261117.war` 无 ai-agent / mcp / skill / llm / vector / embedding 组件；文档「AI 能力」为业务功能。
- 不得把 SKILL.md / 知识包文件当作组件安装；不得宣称被 AI 加载或执行。执行能力未启用 / 受阻。

## 3 常见故障处置（文档记录，执行前须审批 + dry-run）
- **组件上传「主键冲突」**：文档处置为删除组件相关记录后重新上传：
  `delete FROM gdmp.t_gdmp_file_item where file_uri like '%component_package_path%';`
  → 该语句来自排故文档；生产执行须先备份对应表 / 记录、审批、`WHERE` 条件核对后再执行，DB 回滚方案单独制定。
- 手工改库风险：表结构由应用启动时 `GdmpTableMigrate` 自动维护，手工改动可能在重启时被对齐或报错（详见 database-operations）。

## 4 升级兼容性（风险 R6，高）
- 升级后历史**组件**兼容性风险为已登记风险：老组件在新平台版本可能出现不可用 / 显示异常（参考「升级后表格不显示复选框」需跑 Mongo 脚本，脚本内容待确认）。
- 升级前须盘点已安装组件及其版本 / 依赖关系，建立清单并在测试环境验证；生产变更须审批、先 dry-run。
- 数据库（组件元数据 / 文件记录）与应用（组件包 / 静态资源）回滚**分别制定**，不得默认互逆（R7）。

## 5 操作纪律
- 默认只读查看组件清单与依赖；安装 / 卸载 / 覆盖 / 版本变更须审批。
- 组件台账（实际安装清单、版本、依赖、来源、校验值）现场采集后登记；未采集前标注待确认。
